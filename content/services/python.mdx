<ServiceCatalog
  title="How we work"
  intro="Python projects fail quietly when the environment is tribal knowledge. We make the install, the framework, and the job boundary boring on purpose."
  items={[
    {
      title: "Lock the interpreter and the dependencies",
      icon: "/images/services/python/check.svg",
      paragraphs: [
        "The Python version is the one production runs. The lockfile is the install. A developer machine that needs extra undocumented packages is a bug in the repo, and we fix it before adding features.",
      ],
    },
    {
      title: "Choose Django, FastAPI, or Flask once",
      icon: "/images/services/python/check.svg",
      paragraphs: [
        "The framework matches the product: Django for an application with an admin, FastAPI for a typed API, Flask for a small existing or narrow service. Mixing them inside one deployable is not a phase we plan for.",
      ],
    },
    {
      title: "Keep jobs out of the web process",
      icon: "/images/services/python/check.svg",
      paragraphs: [
        "Anything that waits on a file, a large query, or another company's API is a command or a queue task. The web process validates, records the request, and returns. The job reports success or a specific failure.",
      ],
    },
    {
      title: "Test the boundary that can break",
      icon: "/images/services/python/check.svg",
      paragraphs: [
        "pytest, with the database and the HTTP client the code uses. A typed schema is checked against an example payload. A job is tested with the bad file we expect, not only the happy path.",
      ],
    },
  ]}
/>
